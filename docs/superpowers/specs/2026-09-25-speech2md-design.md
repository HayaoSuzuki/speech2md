# speech2md 設計仕様

## 目的と対象範囲

speech2md は、ローカルの音声ファイルを文字起こしし、話者とタイムスタンプを含む CommonMark 文書を生成する Windows 向け CLI である。
主な利用者は開発者本人と社内利用者であり、公開ライブラリとしての API 提供は目的に含めない。

変換処理は完全にローカルで行う。
ネットワーク通信を許可するのは、利用者が明示的にモデルを導入するときだけとする。
通常は最大 1 時間、追加の用途として最大 3 時間の日本語会議を処理対象とする。
ソフトウェア開発用語や英字語を含む発話も想定するが、英語への翻訳は行わない。

初期リリースは次の機能を提供する。

- WAV、MP3、M4A 音声の入力
- whisper.cpp による日本語文字起こし
- sherpa-onnx による必須の話者分離
- 意味を変更しない範囲の句読点、空白、反復、段落の正規化
- 話者とタイムスタンプを含む CommonMark の出力
- モデルの明示的な導入と整合性検証

動画入力、プレーンテキスト、HTML、独自形式、LLM による要約や言い換えは初期リリースに含めない。
ただし、入力媒体、推論エンジン、文書形式、保存先を独立して追加できる境界を設ける。

## 設計原則

コアはファイル、標準入出力、ネットワーク、サブプロセス、OS API を呼び出さない。
I/O をトレイトの背後へ隠してコアから駆動するのではなく、外側のランタイムが I/O を実行し、その結果を値としてコアへ渡す。
この方針は、sans-I/O が示す「I/O を抽象化するだけでなく、データを扱う処理から除外する」という考え方に従う。

コアへは `Path`、`File`、HTTP クライアント、whisper.cpp、sherpa-onnx の型を持ち込まない。
エンジン固有の結果はランタイム境界でコアの値へ変換する。
出力形式のレンダラーは文書値から文字列を作るだけで、保存先へ書き込まない。

初期実装は YAGNI を優先する。
外部公開用のプラグイン ABI、動的プラグイン探索、汎用ワークフローエンジンは設けない。
交換可能性はクレート境界と内部インターフェースで確保する。

## Cargo workspace の構成

Cargo workspace を次の四つのクレートに分ける。
クレート境界によって依存方向を固定し、I/O 型がコアへ入り込むことを防ぐ。

```text
speech2md-cli
└─ speech2md-runtime
   ├─ audio adapters
   ├─ engine adapters
   ├─ output sinks
   ├─ speech2md-formats
   │  └─ speech2md-core
   └─ speech2md-core
```

図の親から子への線は、親が子へ依存することを表す。
`speech2md-core` は他の workspace クレートへ依存せず、`speech2md-formats` は `speech2md-core` だけへ依存する。

**`speech2md-core`** は、文字起こし区間、話者区間、発話、統合済み文書などの値を定義する。
時刻による話者割り当て、隣接区間の統合、本文の機械的な正規化も担当する。

**`speech2md-formats`** は、`TranscriptDocument` を文字列へ変換する。
初期実装は CommonMark レンダラーだけとし、将来はプレーンテキスト、HTML、独自形式のレンダラーを追加できる。

**`speech2md-runtime`** は I/O シェルである。
音声デコード、リサンプリング、モデル読み込み、推論、一時領域、モデル取得、出力保存を担当する。

**`speech2md-cli`** はコマンドライン引数を実行設定へ変換し、ランタイムを呼び出す。
利用者向けメッセージ、進捗表示、終了コードも担当する。

将来の動画対応では、映像を含むコンテナから音声ストリームを取り出すアダプターを `speech2md-runtime` へ追加する。
保存先を標準出力や別のストレージへ広げる場合も、`TranscriptDocument` とレンダラーを変えず、出力先だけを追加する。

## 音声のデコードと中間表現

音声デコードには Symphonia を使用する。
WAV、MP3、ISO/MP4、AAC-LC の機能を有効にし、一般的な iPhone ボイスメモの M4A を扱う。
利用者に FFmpeg の導入は要求せず、FFmpeg への自動フォールバックも行わない。

デコーダーは拡張子だけで入力形式を決めず、ファイル内容を検査して音声ストリームを選ぶ。
入力を 16 kHz、モノラル、`float32` PCM に変換する。
対応外のコンテナまたはコーデックを検出した場合は、識別できた形式をエラーに含める。

正規化済み PCM は処理単位の一時領域へ一度だけ書き出し、読み取り専用のサンプルバッファとして Whisper と話者分離で共有する。
サンプルバッファはファイルのメモリマップまたは同等の単一バッキングストアを使い、各エンジン用の完全な `Vec<f32>` を個別に作らない。
バッファの所有者は `speech2md-runtime` とし、エンジンアダプターは推論中だけ借用する。
ランタイムはすべての借用とメモリマップを解放してから一時ファイルを削除する。
1 時間と 3 時間の入力でピークメモリを測定する。
初期版では二つの推論を順次実行し、CPU コアの奪い合いを避ける。

## 推論エンジンとの接続

文字起こしには whisper.cpp を Rust プロセス内で使用する。
Rust バインディングは `whisper-rs` を第一候補とし、多言語モデルへ日本語を明示する。
初期プロンプトを受け取れるようにし、製品名や技術用語を認識の手掛かりとして渡せるようにする。

話者分離には sherpa-onnx の公式 Rust API を使用する。
話者セグメンテーションモデル、話者埋め込みモデル、クラスタリングを組み合わせる。
話者数は自動推定を既定値とし、正確な話者数を利用者が指定できるようにする。

whisper.cpp と sherpa-onnx の型は `speech2md-runtime` から外へ公開しない。
エンジン更新による API 差分はアダプター内で吸収し、コアのデータモデルを変更しない。

## 時刻と発話のデータモデル

時刻は整数ミリ秒の `Timestamp` と半開区間 `TimeSpan { start, end }` で表す。
エンジン境界で時刻を変換し、浮動小数点の丸め差が区間判定へ伝わらないようにする。

コアの主要な値は次の形を取る。

```rust
struct TranscribedSegment {
    span: TimeSpan,
    text: String,
    confidence: Option<Confidence>,
}

struct SpeakerTurn {
    span: TimeSpan,
    speaker: SpeakerId,
    confidence: Option<Confidence>,
}

struct Utterance {
    span: TimeSpan,
    speaker: Option<SpeakerId>,
    text: String,
}

struct TranscriptDocument {
    title: String,
    utterances: Vec<Utterance>,
}
```

`SpeakerId` は一つの録音内だけで有効とする。
別の録音に現れる同じ番号を同一人物とはみなさない。
話者を確定できない区間は `None` として保持し、レンダラーが `Unknown` と表示する。

## 文字起こしと話者区間の統合

話者割り当てでは、文字起こし区間と最も長く重なる話者区間を選ぶ。
重複時間が同率の場合は小さい `SpeakerId` を選び、入力順序へ依存させない。
最大重複時間を文字起こし区間長で割った比率が設定した閾値を下回る場合は、話者を `Unknown` とする。
閾値は0から10000のbasis pointsで保持し、浮動小数点の丸めを割り当て規則へ持ち込まない。
長さ0の文字起こし区間は、閾値が0の場合を除いて `Unknown` とする。

一つの文字起こし区間内で話者交代が発生した場合は、Whisper の単語時刻を利用できるときに限って境界で分割する。
単語時刻がない場合は、区間全体へ最大重複の話者を割り当てる。
根拠のない文字単位の時刻補間は行わない。

連続する同一話者の区間は、区間間の無音が設定値以下であり、統合後の文章が最大長を超えず、話者交代をまたがない場合に統合する。
`Unknown` は同一人物を示す識別子ではないため、隣接する `Unknown` 同士は統合しない。
本文の正規化は、空白と句読点表記の統一、推論窓の重なりによって生じた隣接する同一文字列の除去、段落分割だけを対象とする。
発話内容から欠けた句読点を推測して追加せず、話者が実際に繰り返した可能性のある表現も削除しない。
フィラー除去、要約、言い換え、誤認識の推測修正は行わない。

## CommonMark 文書の構造

Markdown は CommonMark だけを使用し、GitHub Flavored Markdown などの拡張構文には依存しない。
既定出力は発話順を保ち、各発話へ話者と開始時刻を付ける。

```markdown
# meeting

**Speaker 1**（00:00:12）

今回のリリースについて確認します。

**Speaker 2**（00:00:18）

API 側の変更は完了しています。
```

入力本文に CommonMark の制御文字が含まれる場合は、発話内容として解釈されるように必要なエスケープを行う。
文書生成とファイル保存を分離し、レンダラーは UTF-8 の文字列だけを返す。

## CLI の操作体系

初期 CLI の中心コマンドは次の二つとする。

```console
speech2md model install
speech2md transcribe meeting.m4a
```

`transcribe` は次のオプションを持つ。

```console
speech2md transcribe INPUT
  --output OUTPUT
  --whisper base|small
  --speakers N
  --prompt TEXT
  --force
```

既定出力は入力ファイルと同じディレクトリの `<入力名>.md` とする。
既存ファイルは `--force` なしでは上書きしない。
進捗と診断メッセージは標準エラー出力へ送り、標準出力は将来のパイプ出力用に空ける。

補助コマンドとして、導入済みモデルとバージョンを表示する `model list` と、CPU 機能とモデル整合性を検査する `doctor` を用意する。
モデル削除と自動ベンチマークは初期範囲に含めない。

## モデルの導入と検証

`model install` だけがネットワークへ接続する。
既定では Whisper の多言語 `base`、sherpa-onnx の話者セグメンテーションモデル、話者埋め込みモデルを取得する。
Whisper の `small` は利用者が明示的に追加できる。

モデルマニフェストには URL、ファイルサイズ、SHA-256、対応するエンジンバージョン、ライセンス情報を記録する。
ダウンロードは一時ファイルへ行い、ハッシュ検証後に確定名へ移動する。
中断ファイルまたは破損ファイルはモデルとして扱わない。

`transcribe` はモデルを暗黙に取得しない。
必要なモデルがない場合は、不足しているモデルと実行すべき `model install` コマンドを表示する。

## エラーと終了状態

内部エラーは次の分類を持つ。

- 入力ファイルが存在しない、または読み取れない
- コンテナまたはコーデックが未対応
- 音声ストリームが存在しない
- モデルが未導入、破損、または非互換
- デコード、文字起こし、話者分離の失敗
- 一時領域またはメモリの不足
- 出力先の競合または書き込み失敗
- モデル取得時の通信または検証失敗
- 利用者によるキャンセル

CLI は分類に応じた終了コードを返し、原因と次に取れる操作を表示する。
話者分離または文字起こしの一部だけが失敗した場合も、既定では不完全な結果を完成品として保存しない。

出力 Markdown は一時ファイルへ書き、完了後に目的のファイルへ移動する。
処理に失敗した場合は不完全な出力を残さない。

## 一時データとプライバシー

音声を含む一時ファイルは、OS の一時ディレクトリ内に作成した処理単位の専用ディレクトリへ保存する。
正常終了、エラー、キャンセルのいずれでも、ネイティブ処理から制御が戻った後に削除を試みる。
キャンセルは協調的に扱い、Whisper のコールバックと処理段階の境界で停止要求を確認する。
sherpa-onnx の実行中など、使用する API が中断手段を提供しない区間では、ネイティブ呼び出しが戻るまで待ってから終了する。
強制終了で残る場合に備え、次回起動時に speech2md が作成した古い一時ディレクトリだけを識別して削除する。

変換時のプライバシー要件は次のとおりとする。

- `transcribe` はネットワーク機能を呼び出さない
- テレメトリーを実装しない
- 音声と文字起こし本文を通常ログへ出さない
- デバッグログにも本文を既定では含めない
- 入力ファイルを変更しない
- 一時音声を処理後に保持しない

## テストの層

`speech2md-core` は値だけを使う単体テストで検証する。
時刻区間、話者割り当て、話者交代、`Unknown`、隣接区間の統合、本文正規化、空音声、重複発話を対象とする。
区間統合にはプロパティテストも使い、出力順序、区間の妥当性、文字列の保存を検証する。

CommonMark レンダラーにはゴールデンテストを用意する。
日本語、英数字、CommonMark の制御文字、複数話者、`Unknown`、1 時間を超える時刻、空文書、長い発話を対象とする。
生成結果を CommonMark パーサーへ入力し、構文として解釈できることを確認する。

アダプターの契約テストでは、短い自作 fixture を使って次を検証する。

- WAV、MP3、M4A のデコード
- ステレオからモノラルへの変換
- 16 kHz へのリサンプリング
- Whisper の文字列と時刻の変換
- sherpa-onnx の話者区間の変換
- モデルのハッシュ不一致の拒否

結合テストは短い日本語の複数話者音声を CLI から処理する。
推論全文の一致ではなく、正常終了、発話の存在、話者と時刻、CommonMark としての妥当性、一時データの削除、変換中に通信しないことを検証する。
モデルを必要とする重いテストは通常の `cargo test` から分離する。
GitHub Actions の通常 CI は Linux runner だけを使い、モデル不要テスト、カバレッジ、ランダム順テストを実行する。
実モデル推論は手動起動する Linux workflow、Windows バイナリ、SRV-DB、1 時間と 3 時間の性能測定はローカル検証として分離する。

## SRV-DB を使う外部評価

電気通信大学 高橋弘太研究室の話速バリエーション型音声データベース（SRV-DB）を、任意実行の外部評価に使用する。
音声、原稿、派生音声はリポジトリ、リリース成果物、CI キャッシュへ含めない。

開発者が公式サイトからデータを取得し、`SRV_DB_DIR` でローカル配置先を指定する。
配置先は `.gitignore` の対象とし、通常の `cargo test` と CI はデータを取得しない。
評価手順には、使用したデータセット番号、話者 ID、話速、ファイル名を記録する。

データセット 4 と 5 の男女音声、話者別音声、複数の話速を使い、次を測定する。

- 公開原稿と対応づけられる音声の文字誤り率
- 話速に対する認識の変化
- 検出した話者数と、同じ話者へ同じラベルを割り当てる一貫性
- ステレオからモノラルへの変換
- 実時間係数とピークメモリ

SRV-DB は話者交代の正解時刻を提供するアノテーションではないため、SRV-DB だけから diarization error rate を算出しない。
必要になった場合は、ローカルで作成した正解時刻を使う別の評価として定義し、そのアノテーションもリポジトリへ含めない。

README には、SRV-DB を利用した旨と公式 URL を記載する。

## 性能目標

既定の Whisper `base` と話者分離を含め、代表的な Windows CPU で実時間係数 1.0 以下を目標とする。

```text
実時間係数 = 処理時間 ÷ 音声時間
```

CPU によって結果が変わるため、実時間以内の完了を対応条件として保証しない。
計測した CPU、音声時間、モデル、実時間係数、ピークメモリ、一時ディスク使用量を README に記録する。
1 時間と 3 時間の入力を測定対象とする。

## 初期リリースの完了条件

初期リリースは次の条件を満たしたときに完了とする。

- Windows x86-64 でビルドおよび実行できる
- WAV、MP3、一般的な iPhone ボイスメモの M4A を処理できる
- 日本語の文字起こしと話者分離を一つのコマンドで実行できる
- 話者とタイムスタンプを含む CommonMark を生成できる
- モデル取得以外の処理でネットワーク通信を行わない
- エラー時に不完全な出力と一時音声を残さない
- コア、レンダラー、CLI、音声アダプターのテストが通る
- SRV-DB を使った外部評価手順を再現できる
- README のセットアップ手順だけで利用を開始できる
